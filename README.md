# Личный каталог документов

Семестровое задание № 1 по дисциплине «Технологии и методы разработки безопасного программного обеспечения».

**Тишина Елизавета Максимовна, БАСО-03-24**

В этой работе я сделала консольный файловый менеджер на C# и .NET 10. После входа пользователь работает со своим каталогом: может сохранять документы, собирать их в ZIP и просматривать историю своих операций. Сами файлы хранятся на диске, а учётные записи, метаданные и журнал — в SQLite.

## Запуск

Нужен Linux с .NET SDK 10. Проект проверен на CachyOS. Из корня репозитория выполните:

```bash
dotnet run --project FileManager
```

Для запуска с отдельной тестовой базой:

```bash
TISHINA_DATA_DIR="$(mktemp -d)" dotnet run --project FileManager
```

## Как пользоваться

При первом запуске выполните `register`, затем `login`. Команда `help` покажет доступные действия.

| Команды | Что делают |
| --- | --- |
| `list`, `write`, `read`, `delete` | Показывают, записывают, читают и удаляют файлы. Ввод текста заканчивается строкой `.end`, удаление требует подтверждения. |
| `save-card`, `read-card` | Сохраняют и читают карточку с заголовком и описанием в JSON или XML. |
| `zip`, `unzip` | Собирают выбранные документы в архив и извлекают их в новый каталог. |
| `history`, `history changes`, `history errors` | Показывают личную историю, успешные изменения или отказы. |
| `drives` | Показывает сведения о доступных томах. |

## Защита и ограничения

Пароли хранятся как хеши PBKDF2 с индивидуальной солью. SQL-запросы параметризованы. JSON и XML проверяются до замены файла, а для XML отключена загрузка внешних ресурсов. При распаковке ZIP проверяются имена файлов и объём данных.

Проект рассчитан на локальную работу с доверенным каталогом данных. Он не защищает от прямого изменения файлов владельцем ОС и не восстанавливает согласованность файлов и SQLite после аварийного сбоя.
